# Cross-Origin Resource Sharing (CORS)

## Introduction

Browser single-page applications (React, Vue, Next.js) and third-party web clients hosted on a different scheme, hostname, or port from your SwiftPY backend cannot read API responses or send authenticated requests unless your server returns valid **Cross-Origin Resource Sharing (CORS)** headers.

SwiftPY handles HTTP CORS through **`CORSMiddleware`** (also exported as **`CORS`**) backed by **`config/cors.py`** and `.env` environment variables. By design, CORS in SwiftPY is both **opt-in** (disabled unless you attach the middleware) and **fail-closed** (`allowed_origins` defaults to `[]`, emitting zero cross-origin headers until you explicitly allow trusted origins).

Quick imports:

```python
from swiftpy import CORS, CORSMiddleware
# Equivalent module imports:
from swiftpy.http.middleware import CORS, CORSMiddleware
```

## Creating & Organizing Files

Every project scaffolded with `swiftpy new` includes **`config/cors.py`** and matching variables in **`.env` / `.env.example`**:

```python
# config/cors.py (generated by `swiftpy new`)
from __future__ import annotations

from swiftpy.helpers.helper import env, env_bool

CONFIG = {
    "allowed_origins": [
        origin.strip()
        for origin in str(env("CORS_ALLOWED_ORIGINS", "") or "").split(",")
        if origin.strip()
    ],
    "allowed_methods": ["GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS", "HEAD"],
    "allowed_headers": ["Content-Type", "Authorization", "X-Request-ID"],
    "expose_headers": ["X-Request-ID"],
    "allow_credentials": env_bool("CORS_ALLOW_CREDENTIALS", False),
    "max_age": int(env("CORS_MAX_AGE", "600") or "600"),
}
```

> [!NOTE]
> **`config/cors.py` vs. `CORSMiddleware` internal defaults:**
> A newly scaffolded `swiftpy new` project configures `allowed_methods`, `allowed_headers`, and `expose_headers` cleanly for typical SPA APIs (`["GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS", "HEAD"]`, `["Content-Type", "Authorization", "X-Request-ID"]`, and `["X-Request-ID"]`). This framework repository's starter [`config/cors.py`](../config/cors.py) uses `["GET", "HEAD", "POST"]`, `["Authorization", "Content-Type", "X-Requested-With"]`, and `[]`. If you pass a partial `config={"cors": {...}}` dictionary directly without those keys, `CORSMiddleware` defaults `allowed_origins` to `[]`, `allowed_methods` to `["GET", "HEAD", "POST"]`, `allowed_headers` to `[]`, `expose_headers` to `[]`, `allow_credentials` to `False`, and `max_age` to `600`.

### Environment Variables (`.env`)

For common deployments, configure CORS purely via environment variables without editing Python config files:

```dotenv
# Comma-separated exact origins (scheme + host + optional port, no trailing slash)
CORS_ALLOWED_ORIGINS=https://app.example.com,http://localhost:3000
CORS_ALLOW_CREDENTIALS=true
CORS_MAX_AGE=600
```

You can also override individual keys using SwiftPY's nested environment syntax (`CORS__*` or `SWIFTPY_CORS__*`), including comma-separated lists or JSON arrays:

```dotenv
CORS__ALLOWED_ORIGINS=["https://app.example.com", "https://admin.example.com"]
CORS__ALLOWED_METHODS=GET, POST, PUT, PATCH, DELETE, OPTIONS
CORS__ALLOWED_HEADERS=Authorization, Content-Type, X-Request-ID
CORS__EXPOSE_HEADERS=X-Request-ID
CORS__ALLOW_CREDENTIALS=true
CORS__MAX_AGE=3600
```

| Config Path | Env Key(s) | Accepted Input Formats | Behavior |
|---|---|---|---|
| `cors.allowed_origins` | `CORS_ALLOWED_ORIGINS`, `CORS__ALLOWED_ORIGINS` | `list[str]`, CSV `str`, JSON array `str`, or `None` | Exact origin whitelist (`[]` denies all; `["*"]` allows any origin when `allow_credentials=False`). |
| `cors.allowed_methods` | `CORS__ALLOWED_METHODS` | `list[str]`, CSV `str`, JSON array `str`, or `None` | Sent in preflight `Access-Control-Allow-Methods`. Falls back to `["GET", "HEAD", "POST"]` if unset or empty. |
| `cors.allowed_headers` | `CORS__ALLOWED_HEADERS` | `list[str]`, CSV `str`, JSON array `str`, or `None` | Sent in preflight `Access-Control-Allow-Headers` when non-empty; `"*"` echoes incoming `Access-Control-Request-Headers`. |
| `cors.expose_headers` | `CORS__EXPOSE_HEADERS` | `list[str]`, CSV `str`, JSON array `str`, or `None` | Sent in actual responses via `Access-Control-Expose-Headers` when non-empty. |
| `cors.allow_credentials` | `CORS_ALLOW_CREDENTIALS`, `CORS__ALLOW_CREDENTIALS` | `bool` or `"true"`/`"1"`/`"yes"`/`"on"` (`env_bool`) | Emits `Access-Control-Allow-Credentials: true` on allowed preflight and actual responses. |
| `cors.max_age` | `CORS_MAX_AGE`, `CORS__MAX_AGE` | `int` (or `None` to default `600`) | Preflight cache TTL in seconds via `Access-Control-Max-Age`. |

## Enabling `CORSMiddleware`

`CORSMiddleware` accepts `config: Config` cleanly via SwiftPY's DI container—pass the class directly to SwiftPY's middleware hooks without instantiating it manually.

### 1. Global Application Middleware (Recommended for Web APIs & SPAs)

Attach `CORSMiddleware` globally in `main.py` using `app.middleware([...])` (or pass `middleware=[CORSMiddleware]` to `Application(...)`):

```python
# main.py
from __future__ import annotations

from swiftpy import Application, CORS, RequestId, SecurityHeaders
from routes.api import router as api_router

app = Application(title="SwiftPY API")

# Run CORS on every HTTP request, including preflight OPTIONS, 404, 422, and 500 error responses
app.middleware([RequestId, SecurityHeaders, CORS])

app.include_router(api_router, prefix="/api")
```

Global registration wraps SwiftPY's entire HTTP dispatcher (`_dispatch_http`), so even `404 Not Found`, `405 Method Not Allowed`, `422 ValidationException`, and `500` error responses receive valid `Access-Control-Allow-Origin` headers for allowed origins.

### 2. Scoped to a `Router`, `RouteGroup`, or Single Route

When only a subset of endpoints (such as `/api` routes, excluding `/admin` or internal endpoints) should allow cross-origin browser requests, attach `CORSMiddleware` to a `Router`, `app.include_router(...)`, `@app.group(...)`, or an individual `Router` decorator:

```python
from swiftpy import Application, CORSMiddleware, JWTGuard, RouteGroup
from swiftpy.http.router import Router

app = Application()

# Option A: Constructor-configured Router (keep CORSMiddleware BEFORE auth middleware!)
api_router = Router(prefix="/v1", middleware=[CORSMiddleware, JWTGuard])


@api_router.get("/profile")
async def profile() -> dict[str, str]:
    return {"status": "ok"}


app.include_router(api_router, prefix="/api")


# Option B: Application route group
@app.group("/public-api", middleware=[CORSMiddleware])
def public_routes(group: RouteGroup) -> None:
    @group.get("/catalog")
    async def catalog() -> list[dict[str, str]]:
        return [{"sku": "SP-01", "name": "Starter Kit"}]


# Option C: Single route on a Router (Note: `@app.get` does not accept `middleware=`)
partner_router = Router()


@partner_router.get("/widget-config", middleware=[CORSMiddleware])
async def widget_config() -> dict[str, str]:
    return {"theme": "light"}


app.include_router(partner_router, prefix="/partners")
```

> [!WARNING]
> **Always place `CORSMiddleware` before `JWTGuard` or `AuthMiddleware`.**
> Browsers never send `Authorization` headers or session cookies on `OPTIONS` preflight requests. If `JWTGuard` runs before `CORSMiddleware` (`middleware=[JWTGuard, CORSMiddleware]`), `JWTGuard` intercepts the preflight and returns `401 Unauthorized` before `CORSMiddleware` can respond with `204` + `Access-Control-Allow-*` headers. Placing `CORSMiddleware` globally (`app.middleware([CORSMiddleware])`) or first in the group (`middleware=[CORSMiddleware, JWTGuard]`) ensures preflights short-circuit with `204` and authenticated `401` responses still carry `Access-Control-Allow-Origin` for allowed callers.

Scoped CORS works on matching paths even during preflight because SwiftPY's `Router` automatically synthesizes an `OPTIONS` route carrying every matched route's middleware (`GET`, `POST`, etc.) for that path, returning `204 No Content` through `CORSMiddleware`. Unmatched URLs (`404 Not Found`) do not enter group middleware—use global `app.middleware([CORSMiddleware])` if browsers must read `404` payloads across origins.

## Step-by-Step Request & Preflight Behavior

Understanding exactly what `CORSMiddleware` emits helps diagnose browser console errors quickly:

### 1. Requests Without an `Origin` Header

Same-origin server requests, `curl`, backend HTTP clients, and server-to-server jobs normally omit `Origin`. `CORSMiddleware` passes those requests straight to `next_handler(request)` untouched without adding CORS headers.

### 2. Preflight `OPTIONS` Requests

SwiftPY identifies a browser CORS preflight when **both** conditions hold:
- `request.method.upper() == "OPTIONS"`
- `"access-control-request-method" in request.headers`

Behavior:
- **Origin disallowed (including default `allowed_origins = []`):** Returns `204 No Content` with an empty body and **no** `Access-Control-*` headers. Browsers block the subsequent request.
- **Origin allowed:** Returns `204 No Content` with:
  - `Access-Control-Allow-Origin`: `"*"` if `"*"` is configured (with `allow_credentials=False`), otherwise echoes the exact `Origin` and sets `Vary: Origin`.
  - `Access-Control-Allow-Methods`: comma-joined `allowed_methods`.
  - `Access-Control-Allow-Headers`: omitted if `allowed_headers` is empty; echoes `Access-Control-Request-Headers` if `allowed_headers` contains `"*"`; otherwise comma-joined `allowed_headers`.
  - `Access-Control-Allow-Credentials: true`: included only when `allow_credentials=True`.
  - `Access-Control-Max-Age`: `str(max_age)` (defaults to `"600"`).

### 3. Actual Cross-Origin Requests (`GET`, `POST`, `PUT`, `DELETE`, etc.)

When an `Origin` header is present on a non-preflight request:
1. SwiftPY executes `response = await next_handler(request)`.
2. If the origin is not allowed, `response` returns without any `Access-Control-*` headers.
3. If the origin is allowed:
   - Emits `Access-Control-Allow-Origin` (`"*"` or the matched `origin`).
   - For non-wildcard origin responses, sets or appends `Origin` to `Vary` cleanly (`Vary: Origin`, or `Vary: Accept-Encoding, Origin` when `Vary` already exists) so shared proxies and CDNs do not cache one origin's headers for another origin.
   - Emits `Access-Control-Allow-Credentials: true` when enabled.
   - Emits `Access-Control-Expose-Headers` when `expose_headers` is non-empty (so JavaScript `fetch()` / `axios` can read custom headers like `X-Request-ID`).
4. If response transmission fails before HTTP headers start during `StreamingResponse` error handling, `Application` preserves `Vary` and any `Access-Control-*` headers on the fallback `500` response.

## Testing CORS with `TestClient`

Verify your CORS rules—allowed origins, denied origins, preflight headers, credentials, and `422` validation errors—directly in `pytest` using [`TestClient`](2026-11-19-cli-and-testing.md):

```python
from __future__ import annotations

import pytest

from swiftpy import Application, CORSMiddleware, Response, json_response
from swiftpy.testing import TestClient


@pytest.mark.asyncio
async def test_api_cors_preflight_and_actual_request() -> None:
    app = Application(
        auto_discover_providers=False,
        config={
            "cors": {
                "allowed_origins": ["https://app.example.com"],
                "allowed_methods": ["GET", "POST", "OPTIONS"],
                "allowed_headers": ["Authorization", "Content-Type"],
                "expose_headers": ["X-Request-ID"],
                "allow_credentials": True,
                "max_age": 3600,
            }
        },
    )
    app.middleware([CORSMiddleware])

    @app.get("/api/items")
    async def list_items() -> Response:
        return json_response({"items": []}, headers={"X-Request-ID": "req-1"})

    async with TestClient(app) as client:
        # 1. Allowed preflight OPTIONS request
        preflight = await client.options(
            "/api/items",
            headers={
                "Origin": "https://app.example.com",
                "Access-Control-Request-Method": "POST",
            },
        )
        preflight.assert_no_content()
        preflight.assert_header("Access-Control-Allow-Origin", "https://app.example.com")
        preflight.assert_header("Access-Control-Allow-Credentials", "true")
        preflight.assert_header("Access-Control-Max-Age", "3600")
        preflight.assert_header("Vary", "Origin")

        # 2. Allowed actual GET request
        res = await client.get(
            "/api/items",
            headers={"Origin": "https://app.example.com"},
        )
        res.assert_ok()
        res.assert_header("Access-Control-Allow-Origin", "https://app.example.com")
        res.assert_header("Access-Control-Expose-Headers", "X-Request-ID")

        # 3. Disallowed origin stays fail-closed (no Access-Control-Allow-Origin)
        blocked = await client.get(
            "/api/items",
            headers={"Origin": "https://evil.example.com"},
        )
        blocked.assert_ok()
        assert "access-control-allow-origin" not in blocked.headers
```

## Important Defaults & Security Safeguards

- **Exact origin matching (no wildcard subdomain globs):** `CORSMiddleware` checks exact equality (`origin in allowed_origins`, or `"*" in allowed_origins`). A pattern like `"https://*.example.com"` is treated as a literal string and will **not** match `https://sub.example.com`, and origins must omit trailing slashes (use `https://app.example.com`, not `https://app.example.com/`). List each trusted origin explicitly, or build the list dynamically in `config/cors.py`.
- **Wildcard `*` + `allow_credentials=True` fails closed (`Gate G-3`):** Combining `"*"` in `allowed_origins` with `allow_credentials=True` violates the Fetch/CORS specification and is rejected immediately with `ConfigurationError` at middleware construction and re-validated on every request if `app.config["cors"]` is mutated at runtime. Always list explicit origins when cookies or credentialed requests are enabled.
- **CSV & JSON env safety (`CORE-2` / `INF-3`):** Passing a raw string (`"https://a.com, https://b.com"`) in programmatic `config={"cors": {"allowed_origins": "..."}}` splits cleanly on commas or parses JSON arrays instead of iterating characters, and `"false"` / `"0"` booleans coerce strictly to `False`. Malformed JSON array syntax raises `ConfigurationError`.
- **`allowed_headers` must list custom request headers:** If your frontend sends headers beyond CORS-safelisted headers—such as `Authorization`, `X-API-Key`, or `X-CSRF-Token`—include them in `allowed_headers` (or set `["*"]` if credentials are not used and you intentionally reflect requested headers).
- **WebSockets use a separate origin setting (`Decision D-14`):** `CORSMiddleware` applies to HTTP requests only. WebSocket handshakes validate `Origin` against `Application(allowed_origins=...)` / `websockets.allowed_origins` (defaulting to strict same-origin checking against `Host`). See [WebSockets](2026-11-15-websockets-and-admin.md) for details.
